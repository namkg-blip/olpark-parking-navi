# 올팍 공연일 주차 내비

올림픽공원 공연 날, 언제 도착하고 언제 출발하면 덜 막히는지, 어느 문으로 들어가면 어느 문으로 나오게 되는지를 공공데이터로 미리 알려주는 웹 서비스입니다.
2026년도 한국체육산업개발(주) 공공데이터 활용 경진대회 출품작입니다.

- 서비스: `docs/` (정적 웹, GitHub Pages로 배포)
- 분석·모델: `tools/`

## 사용한 공공데이터

## 정의

- 유효일: 하루 출차 합계가 전체 날짜 중앙값의 40% 이상인 날. 자료 구간 2025-01-01~12-08(마지막 입차 기록 12-07 16:08) 342일 중 241일. 8·9월은 유효일이 하루도 없다.
- 공연일: 연계 데이터에 공연명이 표시된 날 136일(그중 유효일 97일, 평일 27·주말 70). 공연명에 줄바꿈이 든 행이 있어 `build_events.py`는 줄바꿈까지 공연명으로 읽는다.
- 주말 처리: 2025년 유효 주말 70일이 모두 공연일이라 공연 없는 주말이 0일이다. 그래서 주말은 평소 기준선, 초과, 러시, 교차검증, 예측을 하지 않고 공연일끼리의 실측 분포만 낸다(`model.json`의 `weekend_obs`).
- 평소 기준선(분석·검증, 평일만): 공연일마다 앞뒤 21일 안의 공연 없는 같은 요일 유효일의 15분 구간별 출차 중앙값. 그런 날이 2일 미만이면 앞뒤 28일 안의 공연 없는 평일로 대체.
- 평소 기준선(예측 화면): 2025년 같은 달의 공연 없는 유효 평일 15분 구간별 출차 중앙값. 그 달에 없으면(8·9월) 뒤따르는 가장 가까운 달. 11월·12월은 각 4일.
- 출차 최고점: 17:00~23:45 가운데 실제 출차가 기준선을 가장 크게 넘은 15분 구간. 초과가 25대 미만인 날은 사례에서 제외.
- 러시 지속 시간: 최고점 구간 시작부터, 그 뒤 처음으로 출차가 "기준선 x 1.3 + 10대" 이하가 된 구간 시작까지. 다음 날 03:00까지 잰다(다음 날이 유효일이 아니면 자정에서 멈추고 하한값). 심야에는 끝 기준이 15분 약 23대라 잔여 출차가 포함된다. 감도는 `meta.rush_sensitivity`.
- 절반 지속: 최고점 구간 시작부터 출차가 그 최고점의 50% 이하로 처음 내려간 구간 시작까지(기준선 없음). 주말 분포와 평일 비교에 쓴다.
- 가장 붐비는 구간(화면): 예상 출차가 예상 최고점의 50% 이상인 최고점 앞뒤의 연속 구간. 화면은 그 끝을 "가장 붐비는 구간을 피하는 시각"으로 보여 준다.
- 입차 최고점: 공연일마다 출차 최고점 6시간 전~1시간 전 15분 구간 가운데 입차가 기준선을 가장 크게 넘은 구간. 예측 화면은 그 간격의 중앙값(4시간 15분)을 예상 출차 최고점에서 빼서 쓴다.
- 관객 수: 같은 시간대 공연 관람객 합계. 연계 데이터가 같은 시간대 공연을 "A, B"로 합쳐 표시하고 관람객 수도 합쳐 주며, 그날 최댓값을 쓴다.
- 평일/주말: 요일로만 나눈다. 평일 사례 중 2025-05-05, 2025-10-03은 공휴일.
- 건수: `n_records_dedup`(중복 제거 뒤 2,404,915건, 문별 입출 비율 기준), `n_records_analyzed`(입차 2025년이고 출차가 입차 뒤 2일 안인 2,387,938건, 15분 집계·모델 기준).
- 지속 시간 표기: 측정 단위가 15분이므로 중앙값이나 75% 값이 15의 배수가 아니면 "75~90분"처럼 앞뒤 눈금의 구간으로 적는다.
- 비율 표기: 99% 이상은 소수 둘째 자리, 그 밖은 첫째 자리(화면·그림·기획서 같음).
- 문별 공연일 저녁 출차 집중도: 유효 공연일마다 18:00부터 다음 날 03:00까지 그 문의 15분 출차 최고값을 구해 날짜들의 중앙값을 낸 값. 공연 없는 날은 사실상 모두 평일이라 평일 공연일과의 배율(`event_weekday_vs_normal`)만 낸다. 통과 대수이며 대기 시간이 아니다.
- 구역 추정 점유: 동2·북2·남2문으로 입차한 차량만의 15분 단위 (입차 누계 - 출차 누계). 실시간 주차현황 API가 이 구역 값이라 같은 범위로 맞췄다. 기관 안내 주차면은 2,200대. 실시간 값은 화면 표시만 하고 예측에 쓰지 않는다.

## 모델 요약

- 평일 공연일 26건의 초과 출차 곡선을 최고점 기준으로 정렬해 중앙값을 냈다. 최고점 15분 출차 중앙값 302.5대, 같은 시각 평소 32.5대(사례별 배율 중앙값 9.2배), 러시 중앙값 75분(26건 중 15건이 자정 또는 그 뒤에 끝남), 늘어난 출차의 74%(중앙값)가 최고점부터 30분 안에 나감.
- 서비스는 "공연 종료 시각이 속한 15분 구간의 다음 구간"을 최고점으로 두고 그 곡선을 평소 기준선에 더한다. 이 지연 가정은 실제 종료 시각 자료가 없어 확인하지 못했다.
- 관객 수는 평일 곡선의 크기와 러시 지속 시간을 조정한다(관객 수와 초과 출차 최고점의 상관 0.78). 이 선택은 성능을 보고하는 같은 교차검증으로 했으므로 선택 편향이 있다. 공연장은 관객 수 기본값을 채우는 데만 쓴다.
- 예측 출차는 평일 분석 26건의 최고점 15분 출차 최댓값 392대(2025-06-20 18:00, 같은 시각 평소 276대)를 넘지 않게 자른다. 분석 사례 기준의 상한이며 처리 한계가 아니다. "421대"는 출구별 15분 출차 상위 1% 값을 더한 수일 뿐이어서 쓰지 않는다(2025년에 421대를 넘은 15분 구간 20개, 최대 475대).
- 주말은 예측하지 않고 2025년 주말 공연일 70일의 실측을 보여 준다: 저녁 최고 15분 출차 중앙값 357대(하위 25%~상위 25% 326~393.75대, 최대 475대), 최고점 시각 중앙값 20:45, 절반 지속 중앙값 45분(평일 30분).
- 서2·서1·남3·남4문으로 들어간 차는 99.78~99.98%가 들어간 문으로 나온다. 전체 입차의 81.9%인 동2·북2·남2문은 세 문 사이에서 섞여 나오고 다른 구역 문으로는 거의 나가지 않는다. 남2문은 평일 공연일 저녁 15분 출차 최고 중앙값이 78대로 가장 적지만 공연 없는 평일(40대)의 1.95배로 가장 크게 는다.

## 교차검증 (평일, 해당 공연을 빼고 만든 모델로 그 공연을 예측)

| 평일 26건 | 관객 수 사용 | 관객 수 미사용 |
|---|---|---|
| 러시 지속 15분 이내 | 15건 (58%) | 14건 (54%) |
| 지속 시간 오차 중앙값 | 15분 | 15분 |
| 최고점 오차 중앙값, 최고점 시각을 아는 조건 | 41.8대 | 98.5대 |
| 최고점 오차 중앙값, 모르는 조건 | 58.6대 | 102.5대 |
| 15분 구간 평균 오차 중앙값, 아는 조건 | 26.2대 | 32.8대 |
| 15분 구간 평균 오차 중앙값, 모르는 조건 | 37.6대 | 44.5대 |
| 같은 구간을 평소 기준선만으로 예측했을 때 | 44.4대 | 44.4대 |
| 최고점 시각 오차 중앙값, 모르는 조건 | 30분 | 30분 |

모르는 조건은 연계 데이터가 그날 공연명을 표시한 마지막 시각에 다른 공연들의 지연 중앙값을 더해 최고점 시각을 예측한 것이다. 연계 데이터의 시각은 1시간 단위 표시 구간일 뿐 실제 종료 시각이 아니다. 교차검증의 기준선(앞뒤 21일 같은 요일)과 예측 화면의 평소 선(같은 달 공연 없는 평일)은 다르다. 수치는 `tools/model_v2.py`를 다시 돌리면 `docs/data/model.json`의 `validation`에 그대로 나온다.

## 한계

- 주말은 공연 없는 주말이 없어 평소 대비 분석·예측·교차검증을 하지 않았다.
- 평일 26건 중 24건이 금요일이고, 13건은 대체 기준선을 썼다. 대체 기준선 사례는 관객 수와 러시가 커서(관객 중앙값 11,427명, 러시 중앙값 75분) 관객 수 효과와 기준선 차이가 겹친다.
- 8·9월은 기록이 모자라 분석에서 빠졌다.
- 출차 대수는 통과량이다. 대기 시간이나 정체 길이를 잰 값이 아니다.
- 표본 내역은 `data/sample_attrition_2025.md`(모델을 다시 만들면 함께 생성)에 있다.

## 모델 다시 만들기

문화공공데이터광장에서 서비스키를 받아 저장소 루트의 `.env`에 넣은 뒤 순서대로 실행합니다.

```
KEY_LINKED_2025=...
KEY_PERFORMANCE=...
KEY_INOUT_2025=...
KEY_RENTAL=...
```

```bash
cd tools
python download.py KEY_LINKED_2025 10000
python download.py KEY_INOUT_2025 10000
python build_events.py
python build_inout.py
python analyze_rush.py      # data/gate_matrix_2025.csv, data/gate_stats_2025.csv
python saturation_check.py  # (탐색용) data/exit_curve_event_vs_normal.csv
python occupancy_check.py   # data/occupancy_2025.pkl (전체, 동2·북2·남2문 구역)
python model_v2.py          # docs/data/model.json, data/cases_2025.csv, data/sample_attrition_2025.md
python make_figures.py      # proposal/fig (화면 캡처는 Edge 또는 Chrome 필요, --no-shots 로 생략)
```

결과는 `docs/data/model.json`에 저장되고, 페이지는 이 파일만 읽습니다. 서버가 필요 없어 무료 정적 호스팅으로 운영할 수 있습니다.
